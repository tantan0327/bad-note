## 2. UI/UX —— 11/1 までに直す

**2026-10-26 にデモデータを消して 4 タブを実機で見直した。**

### 2.1 初回の 3 分(これが「品質が足りない」の正体)

- [ ] **ホームの主ボタンを 1 つに絞る** —— 初回ホームに塗りつぶしボタンが 3 つ並ぶ
      (大会を登録する / 課題を書く / 練習を記録する。`HomeView.swift:206 / 288 / 503`)。
      **どれも同じ重さなので、どこから始めるのか決まらない。**
      このアプリの入口は「気づいたことを 1 行書く」なので、
      課題がまだ 1 件も無い間は**「課題を書く」だけ `.borderedProminent`**、
      残りは `.bordered` に落とす。課題が 1 件でもできたら今のままでよい
- [ ] **データが無いときに操作部品を出さない** —— 空のときは出さない、というルールの適用漏れ。
      §2(10/11)で層と絞り込み行には入れたが、他に 2 か所残っている
      - 課題タブ: **`searchable` の検索バーが 0 件でも出る**(`IssueListView.swift:160`)。
        探す対象が無い
      - 家トレ: **「今日 / 昨日 / 別の日」の日付カードがメニュー 0 件でも出る**
        (`TrainingView.swift:63-101`)。記録するものが無い日を選べても意味がない
- [ ] **同じ行き先の言葉を揃える** —— いま 1 つの行き先に 2 つの呼び名がある。
      ツールバー側を画面の言葉に寄せる(「追加」は何を追加するのか画面から離れると読めない)
      | 画面 | ツールバー | カードの中 |
      |---|---|---|
      | 課題 | 追加 | 課題を書く |
      | 大会 | 追加 | 大会を登録する |
      | 家トレ | メニュー | メニューを作る |
- [ ] **空状態の押し心地を揃える** —— 同じ「課題を書く」が、ホームでは塗りつぶしボタン、
      課題タブでは**シェブロン付きのリスト行**。面の色も違う(ホームは薄インディゴ、
      空状態カードは白)。`EmptyStateView` の体裁を 1 つに決めて 4 タブで揃える

### 2.2 仕上がりの精度

## 6. やらないと決めたこと

- **めざす姿の画像**(§7.1「+任意で画像 1 枚」)— 2026-08-22 に見送り。
  `PhotosPicker` が SkipUI 非対応で、iOS と Android の両方に自前実装が要る割に、
  テキストがあれば成立する
- **長押しドラッグ以外の並び替え手段の追加** — スワイプ / ドラッグ / 組み替えモードの
  3 つで足りている
- **初回だけのスワイプ / ドラッグのヒント** — 忘れた頃に効かず、消すための状態管理が要る。
  常設の控えめなフッター注記にした。**グリップ ⋮⋮ も不採用**(実際のドラッグは行の
  どこでも長押しなので、開始点だと誤解させる)
- **未整理の課題を層に混ぜる**(`statuses` に inbox を足す)— 整理前の課題が「いつか」に
  紛れて整理フローの意味が薄れる。課題一覧の末尾に独立したセクションで出す
- **チェック済みの行に消し込み線** — 「作業を消す」感が強い。名前を沈める表現にした
- **節目に称号を付ける** — 数字だけにした(このアプリの静かなトーンに合わせる)
- **目標大会を複数にする** — §5.1 の 8 週間切り替えと §4.4 の調整期が
  「種目ごとに 1 つ」を前提にしている。代わりに全大会が「ねらい」を持てるようにした
- **組み替えの候補行に stale / 最後に触れた日を出す** — §4.3 の週 1 回の提示が
  担当している。3 件を選ぶだけの画面に毎行の経過を出すと騒がしくなる
  (判断材料は影響度の目印だけで足りる)
- **書き出した JSON の読み込み(復元)** — `ShareLink` がテキスト共有のみで、
  ファイルの受け取りに両 OS の自前実装が要る。`View/ExportView.swift:67` に明記済み(2026-10-11 確認)
- **初回のチュートリアル画面** — 各タブの空状態 + ボタンで足りる(§2 の課題タブの空状態で揃う)
